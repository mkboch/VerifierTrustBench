The question: when should an AI verifier's conclusion count as scientific verification, rather than merely a correct-looking verdict?

The Verification Evidence Profile

A single accuracy number hides the thing you actually want to know. We report a verification episode as a profile over nine components, because they come apart from each other.

  • Information pathBlind discovery, category-targeted, relation-localized, or supplied by an upstream agent.
  • DiscoveryDoes the system find the defect when nothing is pointed at?
  • RankingIf it was found, where in the finding list did it appear?
  • LocalizationCan the system reach the right lines when it is told what to check?
  • AdjudicationGiven the right lines, does it rule correctly?
  • Evidence responsivenessDoes the verdict move when the underlying evidence changes (E0 / E1 / E2)?
  • ProvenanceDoes the cited line actually carry the tested relation?
  • SpecificityHow often is a perfectly valid relation flagged as broken?
  • Inter-agent transferWhat does one verifier's output do to the next verifier's judgment?

What this page is, and is not

This site ships minimal de-identified aggregate counts — the sufficient statistics for the analyses offered above. It deliberately does not ship model generations, manuscript text, per-case records, the paper's figures, or any human-participant data. GitHub Pages is a public static site, so everything sent to your browser is inspectable by design; the protection here is that only aggregates were ever published, not that they are hidden.

No human-validation module. The study's human validation involved six identifiable colleagues. No human data — not even an aggregate — is published here, so that no reconstruction path exists.

Rates are recomputed from the counts, so a displayed percentage can differ from the manuscript's by 0.1 pp where the manuscript rounded an already-rounded stored rate. The counts are the same.
